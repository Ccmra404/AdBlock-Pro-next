# AdBlock Pro v0.14.1

## 更新内容

本次包含 #57、#58、#59 和 #60。

- 新增“设置 → 应用过滤”，支持按应用名称或包名搜索，选择哪些应用参与本模块的 DNS 过滤。关闭某个应用的开关后，其明文 DNS 请求绕过模块接管，其他应用继续按原规则过滤。
- 应用过滤选择保存后立即刷新接管规则，无需下载全部订阅或重启核心；覆盖升级保留选择，恢复默认设置时清空排除名单。
- 改进 VPN 自动兼容恢复逻辑，恢复接管时同时遵守应用排除名单和用户保存的 DNS 接管开关。
- 修复 Root 管理器中的 VPN 旁路状态描述，VPN 断开、等待恢复、接管关闭等状态会同步更新。
- 新安装及恢复默认设置时，关闭不必要的私网反查和客户端主机名解析，减少本机反查连接失败日志；覆盖升级保留现有配置。
- 完善项目主页的功能介绍、网络排查说明与使用入口，新增自愿捐赠区域。

## 升级说明

版本为 `v0.14.1`，versionCode 为 `53`。可直接覆盖安装，完成后正常重启，保留既有账号、规则源、个人名单、AI 配置、DNS 上游和其他偏好，无需恢复默认设置。

应用排除名单默认为空，所有应用沿用原有过滤范围。应用过滤开关控制的是该应用是否经过模块的明文 DNS 接管；开启过滤后，未命中规则的域名仍能正常访问。共享 UID、系统代发的 DNS、缓存、已有连接和应用内加密 DNS 都可能影响实际效果，不能将此开关理解为严格的应用网络隔离。详见[应用过滤说明](application-filtering.md)。

VPN/TUN 自动兼容默认仍关闭。IPv4 DNS 默认接管、IPv6 DNS 接管默认关闭的策略不变。管理器可能缓存模块描述，返回模块列表并刷新后再查看。

## 验证范围

- 小米 Pad 8 Pro、Android 17、KernelSU 衍生管理器：相同运行时代码候选包已完成安装和重启，核心、TCP/UDP 监听及 IPv4 接管正常；应用列表、搜索、排除保存和恢复参与均已验证。
- Chrome 排除后访问百度正常；DNS 路径对照确认排除请求命中应用 UID 放行规则，参与请求进入模块重定向链。测试结束后已恢复原名单并清理临时规则。
- 本次未新增 Magisk、APatch、移动数据或 IPv6 接管的真机验收。
- 发布包由 GitHub Actions 在最终主线提交构建，并执行 Shell、WebUI、Node、Python、Go、安全扫描、ARM64 安装包结构、凭据排除与 SHA256 校验。

## 回退

如升级后遇到问题，可在 Root 管理器中覆盖安装上一稳定版 `v0.14.0`，再正常重启。安装前导出需要保留的个人名单与配置；不要将“恢复默认设置”作为降级步骤。
