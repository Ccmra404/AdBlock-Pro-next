# 维护内置规则来源

`rules/source-registry.tsv` 保存内置规则及共享规则的下载线路。它只改变下载地址，不修改用户选择、自己添加的来源或个人名单。更新模块后，开启自动规则更新的用户会在下次定时更新时尝试获取；关闭自动更新的用户可手动更新规则。设备必须能访问至少一个清单地址，无法访问时继续使用本地有效清单和已有规则。

线路需要调整时：

1. 核实新链接确实提供对应来源与格式，尤其是 10007 的“保留广告奖励”和 GOODBYEADS 的配套放行文件。不要根据一次超时或单一网络判断链接永久失效。
2. 在 `rules/source-registry.tsv` 中调整对应来源的 HTTPS 线路与顺序，增加 `# revision:` 后的数字。不要删掉来源分组；相同版本号的不同内容会被设备拒绝。
3. 提交 PR，经格式检查与审核后合并。设备拿到更新清单后，会在之后的规则更新中使用新线路，无需仅为换地址发布模块。

清单只接受明确的 HTTPS 域名和无查询参数的路径，不执行远程脚本。设备信任本仓库及配置的清单镜像；HTTPS 不证明镜像内容一定与仓库一致，因此必须审核清单改动并保护仓库权限。自动检查每 12 小时从 GitHub Actions 网络探测线路，也可手动运行工作流；它只报告状态，不会自动改源。GitHub 的网络位置不能代表中国大陆用户网络，需要结合国内网络或用户日志判断。所有镜像都无法连接时，设备可能仍无法下载新内容，但已有规则和本地清单会保留。

获取清单本身的备用地址随模块固定。如果这些地址都长期失效，离线设备无法取得新清单，需要通过模块更新恢复。
