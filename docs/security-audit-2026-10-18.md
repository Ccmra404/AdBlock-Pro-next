# 2026-10-18 代码安全审查

本轮修复两项问题：AI 接口特殊网段校验不足、Go 构建工具链过旧。另有一项上游预编译核心的扫描风险需要跟进。没有发现可据此确认的远程 Root 代码执行；本报告也不构成完整安全认证。

审查基线：main `289e6ed`、PR #22 `16a335f`。地址校验修复位于 PR #22 的 `864a5ec`；工具链修复以该分支为 base，须在 PR #22 后整合，不能与 main 独立混用。正式版本、规则、凭据、IPv6 默认策略均未修改。

## ABP-SEC-001：Go 工具链过旧

- **级别：中；发布 AI 功能前应修复。**
- **位置：** `.github/workflows/release.yml:89`、`.github/workflows/update-adguard-home.yml:28`；AI 请求入口 `tools/ai/main.go:366`。
- **证据：** 审查基线使用 `go-version: '1.23'`；实际 ARM64 AI 产物的 build info 为 `go1.23.12`。官方 govulncheck v1.9.0 对旧产物命中标准库记录，包含 [GO-2026-4918](https://pkg.go.dev/vuln/GO-2026-4918)。该记录描述 HTTP/2 客户端处理异常 SETTINGS 帧时的循环，AI 组件通过 `http.Client` 发起 HTTPS 请求。
- **影响：** 使用旧网络/证书实现存在已知风险；这里未向真实服务商发送恶意响应，也未证明每个扫描命中都可利用。二进制扫描的符号命中数不能视为独立、可利用漏洞数。
- **修复：** 两条工作流统一为官方当前稳定 Go 1.27.2。ARM64 打包前固定安装 govulncheck v1.9.0，对两个模块运行源码调用链检查和同源、保留符号的 ARM64 产物检查；任何检查错误都阻断后续打包。
- **验证：** 新 Go 下 AI、bootstrap 源码扫描无可达漏洞。新 AI 产物和保留符号的 bootstrap 产物扫描通过；源码/产物检查失败阻断流程的回归通过。完整 CI 结果见对应 PR。
- **误报说明：** bootstrap 只导入 x/crypto 的 bcrypt/blowfish。剥离符号的产物扫描会保守报告同模块 SSH/OpenPGP 记录；同源未剥离产物与源码检查无调用命中。未为消除该误报升级无关 API 或关闭校验。

[Go 官方安全维护政策](https://go.dev/doc/security/)只为最近两个主要版本提供安全修复；[当前稳定版本](https://go.dev/dl/?mode=json)在本次核对时为 Go 1.27.2 / 1.26.9。

## ABP-SEC-002：AI 接口特殊网段校验不足

- **级别：中；公网目标限制不完整。**
- **位置：** `tools/ai/main.go:285` 的拨号前校验、`:316–352` 的地址过滤；回归 `TestSpecialUseAPIDestinations`。
- **证据：** 旧实现只检查 `IsGlobalUnicast`、`IsPrivate` 等，纯本地测试确认 `100.64.0.0/10`、基准测试网段、IPv4 映射及包含非公网 IPv4 的标准 NAT64 地址被接受。[IANA IPv4 注册表](https://www.iana.org/assignments/iana-ipv4-special-registry)将共享地址空间标为非全球可达。
- **影响：** 不可信接口域名的 DNS 结果可能让组件尝试连接非公网目标，违背界面的公网接口限制。TLS 证书验证和禁止重定向仍然存在；未确认密钥泄露，也未向元数据地址或其他内部服务发送请求。
- **修复：** 拒绝共享、基准测试、文档及保留网段；规范化 IPv4 映射地址；检查标准 NAT64 内嵌 IPv4，同时保留指向公网 IPv4 的标准 NAT64 访问。继续在拨号前核验全部 DNS 结果并连接已核验的 IP。
- **验证：** 16 个此前放行的拒绝样例现均被拒绝，公网 IPv4、IPv6 和公网标准 NAT64 正向样例通过。原 Go 回归及 vet 通过。
- **兼容边界：** 不支持内网 AI 网关；代理 Fake-IP 落在基准测试网段时也会拒绝，应让该接口返回真实公网 DNS 地址。本轮没有修改任何代理、DNS 或凭据配置。

## ABP-SEC-003：上游预编译核心的扫描风险仍待核验

- **状态：待上游／可达性复核，未宣称已修复。**
- **位置：** `bin/AdGuardHome`、`upstream/adguard-home.json:2`。
- **证据：** 当前官方核心 v0.107.79 的 build info 为 Go 1.26.6。保守二进制扫描命中 18 项记录，涵盖标准库及依赖；尚未做上游源码调用链分析，不能认定这 18 项均影响模块实际路径。此次 GitHub 核对的[最新官方稳定版](https://github.com/AdguardTeam/AdGuardHome/releases/tag/v0.107.79)仍是相同版本。
- **处理：** 保留官方二进制及 SHA256 来源，不静默替换为自编译核心、测试通道或未验证的新架构。跟进官方稳定安全更新，并在独立上游升级 PR 中复核配置、规则、启动及 Android 兼容。
- **缓解边界：** 默认管理端口、DNS 监听仅绑定回环地址，IPv6 接管默认关闭；这缩小暴露面，但不能证明所有客户端上游解析路径无风险。当前审计未对真实设备进行破坏性测试。

## 保留的产品决策与验证边界

- `tools/bootstrap/main.go:13,19` 保留用户要求的首次安装 `admin/password` 和回环管理地址。已安装凭据不覆盖；默认密码对同机程序可猜测，不应把后台对外监听。这是已知产品取舍，本轮未改密码或安全设置。
- 检查过 Root 命令白名单、Shell 参数引用、模型输出 HTML 转义、导入限额、HTTPS CA、AI 日志脱敏及 DNS 停止/卸载失败保护。未发现明显新增 XSS 或 Shell 注入，不等于证明不存在。
- 本轮不改业务界面、默认订阅、规则库、正式版本号或已有 Release；没有连接测试设备，没有读取真实密钥、名单或设备日志。
- Windows/Linux 模拟和 ARM64 CI 不能替代 Android 的网络切换、Root 宿主、后台冻结、异常恢复及真实 AI 接口复测。
