## 新增修复

- 防火墙清理通过完整、有效的 `-S OUTPUT` 快照确认跳转，不再将 `-C` 返回码 1 当作不存在。条件跳转、删除后仍有残留、查询不确定时均不停止 DNS 核心。
- 卸载先尊重正常停止结果，再独立核对自己的 IPv4 跳转及可用 IPv6 表中的遗留跳转。只有明确报告不支持的可选 IPv6 表可以跳过；工具缺失和普通查询错误不视为清理成功，保留运行文件。
- 后台任务结束后强制更新日志缓存；若旧日志请求尚未结束，等待后合并成一次新读取，避免旧响应覆盖或重复重绘。
- Release 测试打包只读权限；只有 main 上手动触发的独立 publish job 可写 Release。发布前核对当前 main SHA、已有 Release/tag、ZIP SHA256 和结构。API 403、超时等错误均停止；不复用已有 tag。
- ARM64 ZIP 验证 module id、候选版本、versionCode、必需安装文件、两个 ARM64 ELF 的可执行权限、完整性及凭据排除。
- 上游更新只修改仓库文件，创建 Draft PR 和未发布测试 artifact，不更新手机、不自动合并、不自动发布。

`scripts/compat.sh`、`service.sh`、`scripts/base.sh`、`scripts/tool.sh`、`settings.conf`、`module.prop`、DNS 核心和随包缓存沿用基线。`customize.sh` 只加强缺失偏好初始化和结果提示；有效的旧 on/off 不改写，无效偏好不静默重置。默认 IPv6 DNS 接管和 IPv6 DNS 阻断均关闭；保留现有 IPv4 启停、监听等待和异常恢复。名单、规则源及缓存、配置凭据、偏好和三份回滚历史不因整合重置。

## Magisk 最终修复

用户提供的真机证据表明 Root、BusyBox、TCP/UDP 监听正常，手动接管后查询统计增加，但 VmRSS 为 0、PSS 为 25,484 KB。VmRSS 是近似统计，不能将 0 或失败当作内存为零。精确诊断从同一次 `smaps_rollup` 读取 RSS/PSS；用同一 PID 和 `/proc/<pid>/stat` 的 starttime 校验，拒绝采集中进程替换、读取错误和 PSS 大于 RSS 的样本。参见 [Linux proc 文档](https://www.kernel.org/doc/html/latest/filesystems/proc.html)。

总览明确标注“RSS 估计”或“诊断采样 RSS”及采样时间；无法读取显示 `—`。每 30 秒轮询不读取 smaps/smaps_rollup、不执行磁盘扫描。诊断样本缓存仅限同一进程实例，重启后失效。

首次安装默认创建 `dns-takeover=on` 和 `autostart=on`，并检查写入结果。已有 off 偏好保留并明确提示。当前没有足够证据解释用户首次测试为何出现 off，不能声称已证实某个初始化原因。状态与诊断统一区分核心停止、监听异常、API 异常、主动关闭接管、关闭后残留重定向、接管失败和未知偏好；主动关闭时核心仍显示运行。

原始本地名单与仓库一致：29 个不同拦截域名，无预置放行域名。只删除随包名单中的重复行，不增补猜测域名。首次安装的 Go 配置新增启用的独立本地个人过滤器，因此无需在线更新也能加载随包名单；升级不改写已有 YAML/名单，更新继续通过模块自有过滤器应用修改，不接管原生 user_rules。三种 Root 的安装回归覆盖离线默认导入、重复安装去重、删除默认规则后不补回、私有白名单与关闭偏好保留。

ARM64 CI 额外以真实 Go 配置生成器及 AdGuard Home 核心启动隔离实例，验证 29 个个人域名首启拦截、更新后的新增/移除/放行以及原生 user_rules 保留。隔离实例仅使用本地过滤器，不修改生产订阅或访问手机。

本轮通过 ADB 确认真我 GT5 Pro（RMX3888）的 Root 域为 Magisk，版本 `e8a58776-alpha:MAGISK:R`；旧模块目录由 KernelSU 继承，不能作为新包兼容证据。候选内存采样脚本在旧引擎同一 PID 上实际读到 RSS/PSS 31,708/31,704 KB，快速读取正确复用样本。已在手机及本地生成并校验完整私有备份。最终测试 ZIP 的重新安装/重启结果将在 PR 记录；不将该脚本单项测试等同于整包验收。

## 自动化与真机的区别

Magisk 重新安装后另发现过滤总开关读取了订阅内的 enabled 字段，可能把暂停误报为开启，设置自动更新时也可能改变过滤偏好。现仅读取 API 顶层布尔值；缺失或异常显示 unknown，并拒绝修改无法确认的偏好。新增嵌套字段、顺序、转义文本及暂停偏好保留回归。设备升级保留原有过滤暂停状态，不静默打开。

实际更新超时回滚后，运行中的核心 fd/3、fd/4 继承了 worker.lock 和 update.lock，导致再次安装在 profiles 初始化阶段被拒绝。长驻核心及观察结果的延迟清理进程现在通过 detach.sh 关闭继承的非标准文件描述符再 exec；保留标准输入输出、参数及进程 PID。Linux CI 使用真实 fcntl/flock 锁和活进程验证，不再只依赖锁模拟；Windows 明确跳过该 Linux 专项。未删除锁文件或绕过互斥。

Shell、Node、Python 检查在 Windows/Git Bash 执行；Node 模拟覆盖三种 Root 的工具选择、配置/日志/worker，以及升级数据保留。它不模拟 Android SELinux、真实权限或锁竞争。

Windows Go 测试中的 POSIX `0600` 权限断言无法通过 NTFS 验证；不削弱这项安全测试。完整 Go 测试、原生 ARM64 AdGuard Home 初始配置验证和安装 ZIP 检查必须以本整合 PR 最新提交的 Linux/ARM64 Actions 为准。最终 run 链接和结果写入 PR，不能引用历史 PR 的绿色结果。

仍需用户真机验收：

1. KernelSU、Magisk、APatch 分别安装/升级，确认凭据、名单、订阅、缓存及历史保留。
2. 重启、无网络启动、Wi-Fi/移动网络切换，暂停/恢复、DNS 核心崩溃和防火墙清理失败。
3. IPv4-only、双栈 IPv6、私人 DNS、VPN 共存；默认 IPv6 旁路仍可能绕过过滤。
4. 快速切页、来源增删、档位切换、后台任务、日志缓存及长时间后台恢复；模拟测试不能证明真机帧耗时。
5. 遗留跳转与卸载恢复；IPv6 后端不可用时无法确认其历史规则，需在目标 ROM 验证。
