# 在 FlClash 开启 VPN 时使用模块

[返回使用指南](guide.md)

如果 FlClash 已运行，但应用无法通过代理访问网站，先确认 **VPN** 已开启。代理核心运行、节点连通或仪表盘显示境外 IP，都不能单独证明应用流量已进入 VPN。

如果开启 VPN 后可以联网，但过滤或域名观察时有时无，可按下面的方法排查额外的系统 HTTP 代理。

## 关闭额外系统代理，保留 VPN

下面的用法已在 Android 17、KernelSU、FlClash 0.9.1 和 AdBlock Pro v0.13.5 的一台设备上验证。其他客户端、版本或配置需要分别测试。

1. 记录 FlClash 当前的网络设置，保留配置备份。
2. 打开 **工具 → 进阶配置 → 网络**。
3. 保持 **VPN** 开启，关闭 VPN 分类下的 **系统代理**。这不是关闭代理核心，也不是把出站模式改为“直连”。
4. 在仪表盘停止并重新启动代理核心，使 VPN 使用新的设置。这个过程会短暂中断代理连接。
5. 确认系统 VPN 已连接，再访问一个平时需要代理的网站和一个国内网站。
6. 在模块中开始一次域名观察，打开目标应用。检查观察结果，并确认正常功能和广告表现。

不要同时更改 DNS、订阅和 IPv6 开关，否则无法判断是哪项设置影响结果。本次验证保留了原有模块配置、订阅和 FlClash DNS 设置。

如果访问或分流异常，在同一页面恢复原来的 **系统代理** 设置，再停止并重新启动代理核心。不要靠反复重启 AdGuard Home 排查代理问题。

## 判断测试结果

- **能联网**：实际访问网站成功。仪表盘“运行中”只表示代理核心状态。
- **经过模块**：观察窗口中出现本次测试域名，且对应 DNS 请求被模块处理。仅有“重定向已应用”不足以证明所有应用都经过模块。
- **命中规则**：检查域名时返回 `FilteredBlackList` 等拦截原因及规则。查询命令成功退出、返回空地址或 NXDOMAIN，均不能单独证明规则命中。
- **广告消失**：需要在目标应用中实际验证。规则命中不能替代广告效果验收。

本次验证中，关闭系统代理并重新连接 VPN 后，Google、GitHub 和百度均可访问。通过 VPN 路径访问测试域名 `doubleclick.net` 失败，模块检查确认它命中规则；10 秒观察记录到了该域名和未过滤的 `example.com`。这些是指定路径的验证结果，不代表所有应用和代理模式均已兼容。

## 仍需注意的边界

FlClash 的 VPN 可以同时向 Android 声明 HTTP 代理。遵守该 HTTP 代理的应用可能直接把域名交给代理解析，绕过模块的 DNS 过滤和观察。关闭上述系统代理设置可以移除这条自动使用 HTTP 代理的路径，但本地代理端口仍可用。

**手动指定 HTTP 或 SOCKS 代理、应用自带的加密 DNS、IP 直连和缓存内容，仍可能绕过模块。** 本次实测中，同一个被模块拦截的域名，显式指定本地 HTTP 代理后仍可连接。

模块的 IPv4 重定向也可能截走原本发往 VPN 虚拟 DNS 的请求，使应用得到真实 IP，而不是代理提供的 Fake-IP。这可能影响依赖 Fake-IP 映射的分流。关闭系统代理并没有消除这个重叠，也不代表完成了 Fake-IP 通用适配。遇到分流异常，先恢复原设置并报告具体客户端与配置条件。

目前不自动改写代理软件配置，不强制接管所有 VPN 流量，也不通过自动关闭模块过滤来宣称兼容。默认 IPv6 DNS 接管策略保持不变。
