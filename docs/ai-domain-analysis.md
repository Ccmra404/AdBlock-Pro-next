# 可选 AI 域名分析

入口在「名单 → 域名观察 → 勾选域名 → AI 分析所选」；接口配置单独放在「设置 → AI 域名分析」。不开启、不填写密钥时，不影响 DNS 过滤、观察和现有名单。

## 配置接口

- DeepSeek 预设：`https://api.deepseek.com/chat/completions`，模型 `deepseek-flash`。
- 其他服务：填写支持 **OpenAI Chat Completions + JSON 对象输出** 的 HTTPS 接口和模型 ID。地址填至 `/v1` 等基础路径时，界面会补上 `/chat/completions`。
- 可使用 OpenRouter 等兼容服务，或自己的 LiteLLM / New API 网关。不代表所有厂商原生协议均受支持，也不需要在手机运行网关。
- 在模块界面填写自己的密钥。修改模型可留空保留同一接口的密钥；更换接口必须重新填写密钥，避免误发给其他服务。

SDK 复用 [go-openai v1.43.0](https://github.com/sashabaranov/go-openai/tree/v1.43.0)，不在模块里安装 Node/Python 或额外代理服务。

## 分析与处理

1. 完成一次域名观察，勾选 1–50 个候选域名。
2. 点击「AI 分析所选」直接进入发送确认，核对接口、模型和数量，再确认发送。调用可能产生服务商 API 费用。
3. 结果区域替换原始观察列表，可点「返回观察结果」切回，不会重新调用 API。查看「疑似广告/跟踪」「疑似正常服务」「无法判断」及理由。域名可能来自后台请求；仅凭域名不能保证判断正确。结果默认不勾选；观察列表支持跨页全选与取消全选，AI 结果可全选可选项，正常服务仍不可批量拦截。
4. 核对后勾选候选，选择「加入个人拦截」或「提交共享候选」。正常服务建议不提供批量拦截入口。

个人导入复用既有合并流程，保留现有名单，跳过重复及与放行名单重叠的项；**保存后自动单独应用个人名单，无需下载或更新其他订阅**。应用只重载本地个人过滤器，不停止 DNS 核心，不修改 AdGuard Home 原生自定义规则或过滤开关。失败时保留保存的名单，尝试恢复原过滤器，可在名单页点「应用个人名单」重试；过滤处于关闭状态时仍保持关闭。共享操作只复制 GitHub Issue 草稿链接，需用户检查并手动提交，维护者审核后才进入共享库。AI 不会自动修改订阅、公开规则或发布 GitHub 内容。

## 数据与失败处理

- 请求正文只附带选中的域名及固定分析提示，不附带应用名、IP、设备标识或原始 DNS 日志。服务商仍能看到建立连接的网络出口地址。
- 密钥保存在 `/data/adb/bindhosts_personal/ai/config.json`，目录权限 `0700`、文件 `0600`。不写入操作日志、浏览器存储、导出名单、安装 ZIP 或 GitHub。
- 只有任务编号写入浏览器存储，以便返回界面继续读取。域名与结果在本机私有目录短暂保留，超过 10 分钟在后续 AI 操作时清理。
- AI 是独立后台进程，使用自己的任务锁；不会停用 DNS 核心或占用规则更新任务锁。它借用已运行的本地 DNS 核心解析 API 地址，核心未运行时分析可能失败。
- 使用随包 CA 验证 HTTPS，不忽略证书错误、不跟随重定向、不自动重试付费请求。仅支持解析到公网地址的接口，不支持内网网关。额外拒绝 CGNAT、基准测试、文档和保留网段；IPv4 映射及标准 NAT64 地址也检查其内嵌 IPv4，指向公网的标准 NAT64 地址仍可使用。
- 超时、认证失败、额度不足、JSON 不兼容、编造/漏掉域名等情况均明确失败，不改变名单。可检查配置后重试，也可继续使用原有「复制给 AI 分析」。

## 验证边界

单元测试和本地浏览器模拟不证明实际服务商可用。真实 API、Android 后台运行及各 Root 宿主仍需配置测试密钥后验收；不要在聊天或公开 Issue 中提供密钥。

个人名单已应用不代表目标广告一定消失。缓存广告、其他域名、IPv6 DNS、加密 DNS 或应用内直连都需要另行取证；AI 输出是候选判断，不是拦截效果证明。
