# 应用过滤范围

在「设置 → 应用过滤」中选择不参与模块 DNS 接管的应用。默认排除名单为空，保持原有全局接管行为。关闭某个应用的过滤后，它的新明文 DNS 请求绕过本模块；开启后重新参与过滤。应用名单与域名白名单相互独立，不会将该应用使用的域名全局放行。

界面提供主用户的应用列表与搜索。已保存但当前列表没有显示的应用仍保留在排除名单，可单独移除；其他用户配置不会因搜索或保存某一项而丢失。后端使用 `用户ID:包名` 保存选择，每次应用规则时通过系统 Package Manager 查询 UID。应用卸载后不沿用旧 UID，覆盖升级保留选择，「恢复默认设置」清空选择并保留原配置的私有备份。

保存时只刷新本模块的 DNS 接管规则，不下载订阅，不清空个人域名名单，也不更改上游 DNS。DNS 接管关闭、核心未就绪、模块禁用或 VPN 自动旁路期间，保存不会强行开启接管；以总览的实际状态为准。保存或应用失败时会尝试恢复原排除名单，界面保留错误提示。

## 范围与限制

- 应用过滤范围仅控制本模块已有的明文 TCP/UDP 53 接管。默认 IPv4 接管与 IPv6 默认关闭的策略不变；手动启用的 IPv6 重定向或旧式 DNS 阻断也遵循同一排除名单。
- 共享同一 UID 的应用会一起被排除，无法仅凭 UID 拆开。系统代发请求或特殊 ROM 也可能无法准确保留应用身份。
- Android 的系统 DNS 缓存可能在同一网络的应用之间共享；已有应用缓存和连接跟踪也可能继续使用旧结果。重开应用并不保证清空系统缓存，排除名单不能承诺严格的每应用解析隔离。
- VPN 代发、私人 DNS、应用内 DoH/HTTPDNS、IP 直连和缓存广告不受这个开关完整控制。界面显示的选择不等于某个广告已经消失。
- 不会为了切换范围而清空系统连接跟踪、重置网络或强制关闭应用。

## 真机验收

候选包合并前，使用两个不同 UID 的应用，针对同一个临时测试域名分别检查新请求：一个参与过滤，另一个排除。交替查询顺序，观察系统缓存的交叉影响；再验证切换、应用重装后 UID 变化、重启以及 VPN 旁路恢复。自动化测试只能验证配置、规则顺序与失败回退，不能代替上述实际效果验证。
